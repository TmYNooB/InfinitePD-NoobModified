# Infinite Pixel Dungeon - Fork Analysis & Development Guide

## Project Overview
**Infinite Pixel Dungeon** is a roguelike dungeon crawler fork based on:
- **Original**: Shattered Pixel Dungeon (00-Evan)
- **Parent Fork**: Experienced Pixel Dungeon Redone (TrashboxBobylev)
- **Current Fork**: DragonMaster14545 (InfinitePD-0.1.9d)

### Key Features in This Fork
- Removal of the cycle limit (infinite gameplay)
- Rarity system for items
- Bigger dungeons (expanded level generation)
- Additional quickslot row (more quick-access items)
- Multi-platform support: Android, Desktop (JAR), iOS

### Current Version
- **Version**: InfPD-0.1.9d
- **Package Name**: com.dragonmaster14545.infinitepixeldungeon.com
- **Version Code**: 692
- **Java Compatibility**: Java 11+
- **Build System**: Gradle

## Project Structure

### Core Modules
1. **`:core`** - Platform-independent game logic
   - Main gameplay mechanics
   - Character system (Warrior, Mage, Rogue, Huntress, Duelist)
   - AI and enemy behavior
   - Dungeon generation and level mechanics

2. **`:SPD-classes`** - Shared classes library
   - Common utilities
   - Base classes used across platforms

3. **`:android`** - Android-specific implementation
   - Android app wrapper
   - APK/AAB generation
   - Android-specific UI adaptations

4. **`:desktop`** - Desktop/JAR implementation
   - Desktop game wrapper
   - Windows/Linux/Mac JAR generation
   - Desktop-specific UI and controls

5. **`:services`** - Service modules
   - Updates service
   - In-game news system
   - GitHub updates integration

6. **`:exception-handler`** - Error handling system

## Compilation & Distribution

### 1. Desktop (Windows/Linux/Mac - JAR)
```bash
# Debug build (for testing)
./gradlew desktop:debug

# Release build (optimized JAR)
./gradlew desktop:release
# Output: /desktop/build/libs/Infinite-Pixel-Dungeon-x.x.x.jar
```

### 2. Android (APK/AAB for Google Play)
```bash
# Using Android Studio GUI or:
./gradlew android:assembleRelease

# For Google Play (recommended):
./gradlew android:bundleRelease
# Output: /android/build/outputs/
```

**Note**: Requires Android SDK, build tools, and proper signing keys for release builds.

### 3. iOS (experimental)
- Build documentation: `docs/getting-started-ios.md`
- Uses RoboVM for Java-to-iOS compilation
- Less maintained than Android/Desktop builds

## Development Guidelines

### Key Files to Understand
1. **`build.gradle`** - Main build configuration, version info
2. **`settings.gradle`** - Module inclusions
3. **`gradle.properties`** - Gradle settings
4. **`core/build.gradle`** - Core module build setup
5. **`android/build.gradle`** - Android-specific build setup
6. **`desktop/build.gradle`** - Desktop build setup

### Important Classes (Core Logic)
- Game main loop and entry points in `:core/src/main/java/com/shatteredpixeldungeon`
- Character definitions: `hero/classes/` packages
- Enemy AI: `mobs/` directory
- Level generation: `levels/` directory
- UI components: `ui/` and `windows/` directories

### Adding New Features
- Game logic → `core` module
- Platform-specific code → `android`, `desktop`, or `ios` modules
- Cross-cutting utilities → `SPD-classes` module
- New item types → Create class in appropriate `items/` subdirectory
- New mechanics → `mechanics/` directory
- New character abilities → `abilities/` directory

### Code Patterns
- **LibGDX framework** is the rendering/game loop foundation
- **Actor pattern**: Most game entities inherit from `Actor` class
- **Event system**: UI and game events use an event/listener pattern
- **Object pooling**: Heavy use of object reuse for performance
- **JSON for data**: Configuration and save files use JSON

## Next Steps for Modifications
1. Identify which module needs changes (game logic → core, UI → ui package, platform-specific → relevant platform module)
2. Make changes following existing code patterns
3. Test with appropriate build:
   - Desktop: `./gradlew desktop:debug` for quick iteration
   - Android: Use Android Studio or emulator
4. Version bump in `build.gradle` (appVersionCode and appVersionName)
5. Build release: `./gradlew desktop:release` or Android Studio's signed APK/AAB builder

## Mandatory Local Change Documentation (for upstream sync)

To keep upstream updates mergeable while preserving local tweaks:

1. For every non-trivial code change, append an entry to `docs/local-change-log.md`.
2. Include:
   - date,
   - commit hash (or "local changes" if not committed yet),
   - exact files changed,
   - gameplay/behavior impact,
   - expected upstream merge risk.
3. If a change touches global scaling or shared systems (e.g., `Dungeon.java`, `Mob.java`, `Hero.java`), mark risk as `high` and describe conflict hotspots.
4. Before pulling upstream changes, review `docs/local-change-log.md` and prepare conflict resolution from those entries.
